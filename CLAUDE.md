# Listula

Shared end-to-end encrypted checklist. SvelteKit 2 / Svelte 5 runes / TypeScript strict.

## Commands

pnpm dev · pnpm check · pnpm lint · pnpm gates · pnpm test · pnpm test:e2e · pnpm build · pnpm budget

`pnpm gates` runs `scripts/gates.sh`, which enforces the rules below that a
linter cannot. CI runs it first, before anything else.

## Version

The number lives in `package.json` and nowhere else. `vite.config.ts` injects
it as `__VERSION__`, the credit in the menu renders that, and the credit test
in `e2e/design.e2e.ts` reads `package.json` back off disk and asserts the two
agree — so the binding is load-bearing rather than a comment, and a number
typed out a second time somewhere would fail the suite. Never add one.

The vocabulary here is its own, and does not follow semver's names:

- **"bump the version"**, or **"major bump"**, moves the middle number:
  `0.1.0` → `0.2.0`.
- **"minor bump"** moves the last one: `0.2.0` → `0.2.1`.

Nothing moves the first number but a decision to call this finished, and that
is not a thing to infer from a batch of changes.

## The gesture reference

`TECHNICAL.md`'s **Gestures** section is the only place the app says what it
answers to. Nothing on the sheet is labelled, there is no help screen, no
tooltip and no empty-state copy — that is settled (§12.14) and is not going to
change — so a gesture that is not written down there is a gesture nobody
outside this repository can find. `README.md` keeps only a plain paragraph of
what the app is and how a list is shared, and links to that section; the
gestures themselves are not repeated there, or there are two records to keep
in step and one of them is always wrong.

**A change to any interaction is not finished until that section says so, in
the same commit.** Not a follow-up, not a later tidy: a reference describing an
app that no longer exists is worse than one describing nothing, because it is
believed. The section says as much of itself, so the promise is on the page.

What counts as an interaction, and so has to be reflected there:

- A tap, a double tap, a long press, a drag or a throw — added, removed, moved
  to a different hit area, or made to mean something else.
- A key: the ladder on a row, `Alt+↑/↓`, `F2`, `Enter`, `Backspace`, `Escape`,
  `Space`/`⇧Space`, or any new one.
- When a control is offered at all — the group's mark only with the group in
  hand, a task's mark only once it is done, the sync button only when it has
  something to say. Availability is half of what a control is.
- What a control's mark reads: `[…]` against `[1/3]` against `[3]`.
- A number somebody would count on: where a row fills up, how many ticks in
  how long raise the offer to clear, how long a message stands. Read every one
  of them off `LIMITS`, `burst.ts` and `ui.svelte.ts` at the time of writing,
  never from memory or from prose — the limits line below said 100 characters
  per task for as long as the code said 200.
- Anything read off the text rather than stored — a count, a price, a total, a
  link — since that is behaviour with no control attached and is therefore the
  least discoverable thing in the app.

What does **not** go there: why it is that way, which belongs in
`DECISIONS.md`, and how it is built, which belongs here or in the rest of
`TECHNICAL.md`. The section says what a finger does and what happens; one
clause of reason where it stops the reader wondering, and no more.

## Non-negotiable

- The share code, derived keys, and plaintext never leave the browser. Server sees ciphertext only.
- The code never goes in a URL — not a query, not a fragment, not the native share link. The invitation's link does carry `?j` (`INVITE` in `src/lib/state/guide.ts`), and that flag has no value and says only that whoever followed it was sent a list; it is not a place a code may ever be put.
- Server code must not import from src/lib/crypto.
- The browser only ever talks to our own origin. No cross-origin requests, no third-party scripts, no CDN fonts — this is what keeps the CSP strict. Nothing carries a blob host URL to the client.
- Palette is #000 and #fff. No greys, no colour, no shadows, ever. Dark swaps which of the two is the paper and changes nothing else — one pair of variables, no second palette to keep in step. **Two carve-outs, and only two, both red and both written over the app rather than into it.** The second is `--guide`, the marks drawn for somebody who arrived on an invitation (`?j`) — an arrow to the burger with JOIN LIST at the far end of it (word for word what `menu.joinList` says), then a ring thrown round the code field with PASTE HERE written under it and to the left. The panel gets no arrow: one there had to end on a field a few millimetres tall, so its head came out smaller than what it pointed at. It is on screen for one arrival, writes nothing, never takes a press, and is the one place the greyscale assertion in `e2e/design.e2e.ts` was relaxed: the exemption is named (`[data-guide-ink]`) and is paired with a test saying nothing anywhere is red until somebody arrives that way. Widening either half is how two colours becomes three. The first carve-out is the debug switch, which outlines every box in red (`:root[data-debug] *` in app.css). It is a tool for whoever is building the app rather than a state the app has, red because an outline in the ink would read as a drawn rule and be the very thing a layout needs telling apart from, and inert unless somebody asks for it. **Being a tool and not a state, it is not on the panel until it is on**: a long press on the burger turns it on — the switch lives in the menu, and that is the menu — and the button it then puts there is what turns it off. The press swallows the tap that would open the panel, and `longPress` buzzes on the threshold, which is the whole of what says it landed. The greyscale assertion in `e2e/design.e2e.ts` reads colour, background and border and never the outline, so it did not have to be relaxed to let this in — and must not be.
- No image files, no icon fonts, no CSS borders on drawn elements. Every mark is an inline SVG path from src/lib/draw, seeded by a stable id so it never re-jitters.
- **The paper is torn, not drawn torn, and the teeth are what cuts.** What is past the tear is not paper: `TornEdge` closes its own zigzag along the **outer** edge and fills that side with `--paper`, so writing travelling that way is cut tooth by tooth. Both halves have to be true or neither is — the panel's scroller runs the full height of the paper, tears included (`.menu` pads by `--paper-top`/`--paper-bottom` alone and `.scroll` holds the tears' own height as its own padding, so a line rests where it always did and only the room above it scrolls away). Stop the scroller at the inner edge instead and the writing vanishes along a straight line a tooth's height short of the teeth, which is a white rectangle doing the tear's work. Nothing is filled on the inside; the paper's ground is already there. **The side edges run up into the tears and are cut back by the teeth** — stopped flush they ended on a clean horizontal, which is a sheet guillotined at three edges and torn at the fourth. Both tears therefore have to be painted over the sides: the panel writes its sides first and needs nothing else, while the sheet lifts both tears instead, since one is above the paper in the flow and one below it. The ground closes a full tear past the box rather than flush at it, because the box is `overflow: visible` and a side's round cap reaches beyond its own. **The tears stop on the two verticals rather than running past them** — trimmed by half of `--edge`, which is where a side's stroke runs in its own box — so the ground carries a strip past each end, down as far as the corner the zigzag made there and no further: below the corner the side is the paper's own edge and has to be seen. Only outside the tear's span, never one rectangle across the width, which would cut the paper straight along the midline wherever a tooth reached above it.
- Merge logic in src/lib/doc/merge.ts is pure and must stay commutative, associative, idempotent. It takes no clock — skew clamping and tombstone GC are separate functions applied by the sync and write paths.
- Collapsed state is local, never synced. So is the theme, which LEAVE does not clear either — removing a list from a phone is not a change of mind about how the phone should look.
- Clearing sweeps done tasks only, and it is **not in the menu** — the group's own mark does it, narrowed to that group, and a run of ticks offers the same for what was just ticked (`clearDone` takes the ids). LEAVE is local-only and never calls the server. Undo re-stamps forward, never rewinds.
- Enter means "and the next one": on a task it commits and opens a fresh row directly beneath, and on a group title it commits — opening a task at the top **only when the group is empty**, since naming a group and writing the first thing into it is one motion and an empty group is the only time the next thing is certainly a task. On a group that already has tasks, somebody there came to change the name and Enter is how they say they are done. Both commit in the keydown rather than through blur, or the blur closes the row that just opened.
- Deleting a group takes its tasks with it. A group is only a name and an order — marking it deleted alone leaves its tasks orphaned into Loose ends, which is how emptying a finished group poured its done tasks back onto the sheet under another heading. Undo puts the group back and then the tasks.
- Animation is opacity and scale only, never a colour or a shadow, and every one asks `prefers-reduced-motion` in JS rather than hiding itself in CSS — a flourish cleared by its own `animationend` never clears if it has no animation to end. Two things turn, and the line between them is what is turning. **A mark never does.** The one rotating mark is the sync button's circular arrow while a sync is in flight: it is a stroke that came round, and turning is what it already means. Nothing else drawn may — the outbox arrow cannot without pointing somewhere it does not mean, and the crossed circle would read as a mark being scribbled out. **The paper does**, when the menu opens: a sheet has two sides and the panel is the second one, so turning it over is not a flourish put on the object but the object doing what it is. One duration for the marks, so the corner reads as one thing working, and one for the turn (`--flip`), which is half of it because the turn is in two halves.
- **The menu is the back of the sheet, and opening it turns the sheet over.** The sheet folds edge-on about its **vertical middle axis** and the panel opens back out about the same one — `.turning`/`.returning` in `+page.svelte`, `.unfurling`/`.furling` in `Menu.svelte`, half of `--flip` each. The middle and not an edge: a receipt turned over is held in the middle and spun, where a sheet hinged at a side is a door or a page in a book, which is a different object. They are two elements and not one, because the sheet is in flow and scrolls while the panel is fixed to the viewport, and one `preserve-3d` box around both would mean laying the page out around the animation. **Every half-turn is the same movement, and the paper only ever spins one way.** A hand pushing the paper rightwards sends the side under it back and brings the far side forward, the way a revolving door goes — so the face on its way out leads with its **left** edge and goes to edge-on (`0 → 90°`), and the face arriving settles out of its right (`-90° → 0`). Opening and closing are therefore identical — the paper does not know which side it is on — so a swipe rightwards always spins it the same way, and swiping again keeps it spinning rather than winding it back. Note the sign flip at each join: `.turning` leaves the sheet at `90°` and `turn-back` picks it up at `-90°`, a quarter further round rather than a quarter back. Nothing is seen of that, since both are edge-on and the sheet has no width at either. The near edge does change sides at the join, because the panel's words are set to be read and not mirrored — also invisible, for the same reason. Nothing turns past a quarter, so no content is ever shown from behind. `transform-origin` is `var(--axis) var(--eye)`. The Y half is not the axis — a `rotateY` is the same rotation wherever the origin sits vertically — but the vanishing point, which `perspective()` also takes from the transform-origin and which on a sheet as tall as its list would otherwise sit a screen below the reader. The X half is the axis, and it moves: a hand pushes it off the middle and `recentre` in app.css brings it back under `--inertia`, on a shorter clock than the turn so it is home before the paper is edge-on. That is the one animation both halves share by name rather than by copy.
- **The edge coming forward is drawn heavier as it comes; the one going away is left alone.** A rotation cannot say on its own which side of the paper is nearer — a vertical stroke's width is measured across, so the same turn that ought to thicken the near edge compresses it, and both sides come out thinner than they started. `--turn` is registered with `@property` so it animates, the transform is a plain rule reading it, and the near edge's weight is a reading of it too — one number, one place, for a finger and an animation alike. **What is `--near-peak` is what reaches the screen**, not what is drawn: the wanted multiple is stated in what the reader sees and the geometry is divided back out of it, `cos` for the compression and the square of the distance ratio for the perspective, so the drawn stroke stands at the cap by the time the paper is edge-on. `--half` is half the paper's width in pixels, which only JavaScript can measure. Which edge is near is the sign of the sine and needs no state: `max(0, sin(--turn))` on the left, its negation on the right, so the far edge falls out at nought and the correction — weighted by `--near` — never reaches it. This is the one animation that is not opacity, scale or the turn itself: it is the weight of a drawn line, which is what a nearer line looks like in a drawing.
- **The turn gives way to anything picked up after it armed.** It arms on `pointerdown` and asks then whether something is already being carried, but a lift takes most of a second, so the press that becomes one is a press the turn has already accepted — and a group title is a span with a button's role rather than a `<button>`, so it is not among the controls the turn stands aside for. Taking the capture over hands it to `main`, the title loses it mid-carry, and `lostpointercapture` puts the whole lift down: a group dragged sideways goes dead the moment it moves. The question is asked again on the first move. The other way round is `drag.turning`, which the page sets for as long as the paper is turning, sliding or swinging home and `pressDrag` refuses a press on: a lift and a turn take about the same half-second, so a press held through a swipe came up carrying a row of a page that was edge-on, steering by a hit test reading boxes off it mid-rotation. Refused, not swallowed — the release is still a tap.
- **A drag rightwards turns the receipt over, from either face.** The sheet is dragged aside to bring the menu up and the panel is dragged aside to put it back — one gesture, whichever side is showing, and the rotation follows the push rather than opposing it. **A sheet pushed sideways goes sideways first**: the paper slides before it begins to turn, and nothing is weighted while it is only sliding, because a paper that is not turning has no near edge. How far it may slide is the room between its own drawn edge and the screen, capped at `LEAD` — it never slides off, and on a phone, where the paper is drawn almost to the edges, running out of room after a few pixels is what starts it turning. The arithmetic is in `src/lib/turn.ts` and is read by both; only the sign differs, since the two are halves of one rotation. **The two faces draw the line in different places, and that is not an oversight.** On the sheet it takes hold on bare paper only (`closest('input, textarea, button, a')` bails), because every control there already owns a press — the long presses that lift a task and a group. On the panel it takes hold over the buttons too: nothing there owns a press, every button is a tap and nothing more, and most of the panel is buttons, so a gesture that only worked in the gaps between them was a gesture that mostly did not work. A drag that crossed a button is not a press of it, so the click is swallowed in the capture phase — the same thing the sheet does after a row is dropped. Text fields keep their own drag on both, which is selecting text. The sheet gives the gesture up at the first sign of vertical movement, since the sheet is what scrolls. Both sides take `setPointerCapture`, and both take it on the **first move rather than on the press**: turning the paper takes it out from under the hand, and without capture the release is never heard and the paper hangs mid-turn — but capturing a pointer retargets the click that follows it, so taking it on `pointerdown` stops every button under the finger from working.
- **The sheet is prerendered, so it may not carry a `style:` directive.** Svelte renders one as a literal `style="…"` attribute in the shipped HTML, which `style-src 'self'` refuses. `--turn`, `--axis` and `--eye` are written onto it through the CSSOM instead. The panel is free to use `style:` because nothing is open when the page is built, so it is never server-rendered. `e2e/csp.e2e.ts` is what catches this.
- **A mark that is working boils.** The technique is one module — `src/lib/draw/boil.svelte.ts`, which holds the four drawings, the beat and the ticker — because two marks drawing it twice is two techniques the moment one of them is retuned. The sync button's three marks are each drawn four times over — four seeds, and four different degrees of looseness, because a seed alone only moves the same wobble to different places and four frames drawn to one setting differ about as much as four copies of a printed line — and cycled while a sync is in flight — the same hand redrawing the same mark, which is what makes a line look alive in hand-drawn animation. It replaced a pulse that grew and faded them: scaling and fading a drawing is a machine moving a picture of a line, and it was the one thing in the corner that never looked drawn. The cycling is done in the markup, not in CSS, because it is a change of drawing rather than of shape and no keyframe can swap one path for another. Frame 0 keeps the bare seed, so a mark standing still is the mark it has always been, and `prefers-reduced-motion` never starts the interval. This is the one place the "seeded so it never re-jitters" rule is deliberately inverted: re-jittering _is_ the animation, and it is confined to the four drawings made up front. **A working mark is also dotted** (`.drawn--dotted`), because a mark that is working reads lighter than one standing still and opacity cannot say that here — a faded stroke on two colours is a grey. It is the same ink laid down less often: a zero-length dash under the round cap `.drawn` already sets, so every dot is the width of the stroke itself. Never `.drawn--faint` for this. The gap and the offset shift frame to frame like the seed and the wobble do, or one pattern held across all four is a stencil over a wobbling line rather than a pen skipping somewhere new. Solid the moment the sync ends, and solid throughout under `prefers-reduced-motion`, which never leaves frame 0. **The corner fold's bin boils too**, and it is the only other mark that does: it is what says a group is over the fold, in place of the weight change every other offer on the sheet uses. It is never dotted — the dots are the sync marks saying they are mid-flight, where the bin is saying "here", which is a different sentence.
- **A move leaves a message with a way back**, and only a move made with a finger: where a task came from is two strings read off it before it goes, and putting them back is an ordinary move stamped now rather than a rewind. A drop onto the new-group row unmakes the group it invented, after the task is out of it. The keyboard's Alt+↑/↓ announces where the task went instead — it is exact, and a run of them would raise a message a step.
- **A group in hand is offered the corner, and the corner alone changes to say so.** The theme and the burger leave the moment a group is lifted — neither has anything to say to a group being carried, and between them they occupy the only place the answer could go — and the paper's top-right corner turns down in their place. Neither the leaving nor the fold is animated: it happens under a finger that is already moving, and a corner is either turned down or it is not. The fold is drawn the way the tear is (`CornerFold.svelte`): the ground is closed past it and filled with `--paper`, so the torn edge and the side edge are cut **on the diagonal** rather than drawn over. **The corner that came over brings its own edges with it** — the paper's corner is reflected across the crease, which carries the torn top edge round to run _down_ from the crease's top end and the side edge round to run _in_ from its bottom one, both drawn with the same `handTear` and `handVertical` the paper's own edges are. A plain triangle would be a corner guillotined off and laid back down. **The mark is a bin (`handBin`), not the scribble**, and it stands in the room the fold clears rather than on the flap: a scribble is a mark made _on_ something and belongs beside the row it strikes out, where a corner with the paper off it is a place, and what a place to be rid of things looks like is a bin. Always full ink — it was faint while it was only an offer, on the rule the add row's box follows, but that box is a suggestion of something not there yet where this is a bin that is there whether or not anything is going into it, and a faint one read as a control not yet available. What says a group is over it is the mark boiling — and the phone, which taps once as the group arrives, because the corner is the one offer on the sheet that cannot answer by changing weight and a change of drawing is the slowest thing here to read. On the **edge** and never on the state, or a finger held there buzzes on every move the browser reports, which is a rhythm and a rhythm is a notification. Letting go answers with `taken()`, the same two beats the header's own mark uses, called at the drop site rather than inside `removeGroup` because the corner is not a button and nothing else on the way in would say anything. **The hit area is the fold's own square** — the flap and the room it clears, stopping at the crease's two ends rather than at the box the fold is drawn in: the top of the list is directly under the corner. A group let go on the fold is removed, tasks and all, **whatever state it is in** — the one rule the header's mark does not follow, because that mark is drawn beside a list somebody may only be reading and this is a group already in hand. Undoable, like everything else that takes something away.
- **A group carried onto the switcher moves lists.** While a group is in hand the pill wears a dashed loop — `handOval`, off level, because a box is a frame put round the words and a loop is somebody's pen going round them once. **It is one size, whatever the list is called** (`--loop` on `.switcher.sheet`): a loop measured off the words was a tight ring round a short name and a long flat ellipse round one that filled the line, which is not one hand making one gesture. A pen circling a word draws about the same loop every time and lets it fall where it falls, crossing the letters at either end when the name is long. **The lists themselves are not shown until the group reaches it** — a column standing open for the whole of a drag lies across the sheet the group is being carried over, covering the titles a drop between two groups is aimed at and answering the hit test before they do. Over the pill it unfolds into the same column a tap opens, ground and rows and all, and over one of those rows **the line under that row goes dashed** — the rule under a name is that name's own line, where a box round the words read as the name having been selected; take the group back to the sheet and it shuts. `data-switcher` is on **both** the wrap and the column, and the hit test reads them as one box round the pair (`overSwitcher` in dnd/drag.svelte.ts) rather than hit-testing each: the column hangs below the pill and is several times as wide, so the two leave a corner of nothing between them and a finger going diagonally from one to the other fell through it. Letting go on the pill itself does nothing: the switcher answers a group by unfolding, and only a list takes one. `NEW_LIST` is a sentinel list id for the same reason `NEW_GROUP` is a sentinel group id. **The column holds every list but the one it was opened from**, in both modes: the pill a centimetre above says which list this is, so repeating it there answered "which one am I on" twice, one of those a row that did nothing when tapped — and with it gone nothing in the column is ever `aria-selected`, which is stated rather than left off because the role requires it. **`+ NEW LIST` is the last row and not a button**: it was centred words in a drawn box, which made the one control in the column look like one and so made every row above it look like something else, when all of them are the same kind of thing — somewhere to go. It is left where their names are and ruled off underneath like theirs; the `+` stands where the others have their first letter and is `aria-hidden`, so the name read aloud stays the plain words. **The column is the full width of the writing**, on both faces — the paper's own width less `--corner-x` at each side, which is where every line on either face begins and ends. Not the pill's width and not its own contents': fitted, the tapped column and the carried one came out different widths and a code appearing moved the edge, and a drop target that changes width under the finger steering at it is worse than a long name losing its tail to the ellipsis the pill above already uses. **The sheet's copy hangs out of the flow and the panel's stays in it**, and that is not an oversight: the sheet's opens over a list a carried group is being steered across, where a column that pushed would move the very thing being aimed at — the panel has nothing being aimed at, and it must make room, because it rules its sections off with a full-bleed perforation and an opaque column laid over one cuts the middle out of it and leaves its two ends sticking out either side. The panel's column is therefore wider than the box holding it (the settings row reserves the ✕'s column and carries the theme) and simply overflows the wrap; **`.pill` is capped with `max-width` rather than stretched with `width`** so the wrap cannot take the pill with it when it grows, since the pill is the one thing on the panel that has to come out exactly as wide as it is on the sheet. One consequence to keep in mind: at this width the open column lies over the first group's title, and the hit test reads the pill and the column as one box, so "back to the sheet" means below the column rather than merely off the pill. The switcher is shown for this even at one list, or the way to a second is missing from the device that has never had one, and it is withheld while `sync.busy`. The column is out of the flow, or it moves the list the finger is steering by, and it is never wider than the paper — the cap is the row's own width less the sync mark's, and a name too long for it is cut with an ellipsis exactly as the pill above cuts one. **It is the same column a tap opens**, on the sheet as in the menu: the sheet's used to be a full-screen modal, which is for something that has to be settled before anything else happens, where choosing which list you are on is a glance at four names — and a tap opening one thing while a drag opened another was two answers to one question. `handOff` in `src/lib/doc/handoff.ts` is the move: the group and its live tasks are written into the other document as **fresh records** — every id, every word, every half-done state — and deleted here through the ordinary path, so what stays behind is tombstones. Fresh rather than moved, because the destination may hold tombstones under those ids from an earlier visit and a record stamped now is what beats one stamped then. **The list being arrived at is written before the list being left**: a group on both lists is something a person can sort out, a group on neither is writing gone. The undo is two ordinary changes and never a rewind — the group is taken back out of the other list, since that list may have been synced since, unless the drop invented it, in which case it is unmade whole after the group is out of it. **The list arrived at then wears an asterisk before its name until the tab is closed** (`lists.arrivals`, and `arrived`/`takenBack`/`isNew` beside it): sending a group away is the one change here that cannot be looked at afterwards, and the message saying where it went is gone in ten seconds. Session state, written nowhere — it is a fact about this reading of the app rather than about the list, the same rule the collapsed groups follow — and an array rather than a set, because two groups can be sent to one list and taking one back does not mean nothing arrived. The mark is a character and lives **inside** the name's own span, not beside it: out there it takes the row's flex gap, which is the gap between two things at opposite ends of a row and is what stood the `+` off in a column of its own; in there it also cannot be reached by the ellipsis. It pushes the name along rather than being given room on every row, which is the rule a task's count follows. `aria-label` names it in words and the character is not read.
- **A run of ticks offers to sweep itself**: three inside five seconds (`src/lib/state/burst.ts`), and the offer clears exactly those, checked against what is still done when it is tapped. Offered, never done, and once per run — a message that swept the sheet by itself would be the app deciding, and one per tick after that would be nagging.
- **A lift is put down when the node holding it leaves.** `pressDrag`'s cleanup resets the shared drag if this node was the lifted one, and `lostpointercapture` does the same if the browser takes the pointer away instead. Without the first, a node that goes mid-lift — a title swapped for its own edit field, a row that changes which element it draws — leaves a lift nothing can clear: no pointerup, pointercancel or capture loss ever reaches those handlers again, and because the lift is one shared state what is left behind is every group folded shut and a dashed outline round a title, for good. `stop()` therefore clears `lifted` **before** releasing a capture, so the `lostpointercapture` its own release fires cannot reset the drag out from under a drop still to be delivered.
- **The group title's press has two lengths.** Let go after `LONG_PRESS_MS` and it opens the name; hold to `LIFT_MS`, which is twice that, and it picks the group up. A buzz at each threshold, since nothing on the screen can say which stage a finger is in. It answers on release rather than at the first threshold, because nothing there knows whether the finger is staying down — and because opening the name takes the node out of the document, which would leave the second press nothing to fire on. The click that follows either stage is swallowed, or the group folds underneath what the press just did. This is the only control with two presses in it: everything else lifts at `LONG_PRESS_MS`, and can, because holding it could not mean anything else.
- Three long-presses, separated by hit area: on the checkbox it sets half, on the row text it lifts the task, on the group title it lifts the whole group. Never merge them. The click that follows a drop is swallowed, or the button under the finger opens.
- **On a task's words the ladder is one tap to open, two to mark it done, three to mark it half.** A list is read far more often than it is ticked in one go, and the row already carries a checkbox whose whole job is the tick — so the words answer the thing the words are for. Taps two and three land on the textarea the first tap opened, so the count lives in the component and the handler is bound to both: the finger has not moved and does not know the element under it has. A run that begins inside an already-open field is disarmed, because that is somebody placing a caret or double-tapping to select a word. **A run that begins in the last few characters is disarmed too** — that is a hand reaching for the end of the task, to add to it or to press Enter and start the next thing there, and two taps in that stretch are two attempts at the same thing rather than a tick.
- **A task pulled leftwards is ticked off, and the row gives while it is pulled.** The words are pushed towards the box at the head of the row and the box takes the tick, which is the whole of why the pull goes this way: rightwards is already the paper turning over, and on a row that draws a link the two begin on the same element, since the words there are a plain container rather than a button and so are not among the controls the turn stands aside for. `drag.swiping` is the answer to that, and it is `drag.turning` the other way round. **Nothing waits.** The tick lands the moment the hand passes `REACH` (`src/lib/dnd/swipe.ts`), under a finger that is still moving, with the buzz that says so — held back for the release it would put a wait on the one thing the gesture is for, and past the reach there is nothing else the movement could turn out to have been. **One pull ticks it off and the next takes it away**, offered on exactly the rows the delete mark is and for the same reason: getting rid of a task is earned by the task being finished with. It **does not stand in for that mark**, which is drawn through both pulls — the pull is the way to it for a hand already moving and the mark is the way for one that is not. The second pull goes out through `pop()`, so the pop, the answer from the phone and the undoable message are the delete that was already there rather than a second one written beside it; `home()` therefore stands aside while `going`, or a row swings back into place while it is being deleted, and `settled` only answers its own animation, or the pop's end stands the row back up for the frame before it goes. **The direction is asked once**, when the movement first passes the slack, and the answer holds to the end of the gesture — a scroll that wanders sideways is still a scroll. **How far the row may go is the paper's, not the hand's**: it slides into the margin the writing is held off the drawn edge by (`--paper-inset`, the column every delete mark stands in) and stops there, capped in the stylesheet, while the hand carries on to the reach. It shares nothing with the three presses on the same row — a press is stillness and this is movement, so the press has given the gesture up by the eighth pixel — and the click that would follow is swallowed in the capture phase, the way a drop's is, or every pull would open the row behind the tick it just made. `pressDrag` therefore releases only a capture it took itself: released on the pointer id alone it took the pull's capture away with it.
- **Elsewhere one tap still does the common thing and two open it for editing.** On a group title the tap folds the group and two taps open the name; on the checkbox the tap ticks, two taps set half, and so does a long press. All three are optimistic — each tap acts and the next takes it back — because holding a tap back a third of a second puts that lag on the action people came to perform. The group title was the one exception, held back for the window on the reasoning that a whole list folding and unfolding is a worse flicker than the wait; the lag is what people actually notice, and they notice it most beside the fold icon two millimetres away, which has always answered at once. **It tells the second tap by `event.detail`, never by timing.** The browser's own click count is exact; a window cannot tell the second click of one pair from the first of the next, and two deliberate double taps a tenth of a second apart happen. One window (`DOUBLE_TAP_MS`, 320ms) still governs the ladders that count their own taps, named once beside `LONG_PRESS_MS`, because it is one finger.
- The group header is three controls: the title, which folds on one tap and renames on two; the icon beside it, which folds on one tap for anyone who would rather aim at it and folds **every** group on a long press; and one mark out in the delete column. Getting rid of a group has a second way in — the corner fold, above — and the two do not answer to the same rule: the mark is earned by the group being finished, the fold is asked for by a hand already carrying it. **That mark has two jobs and is never drawn without one**: it clears the group's done tasks while there is still something in the group to do, and removes the whole group once there is not. Nothing done and something left to do means no mark — the same rule a task's own mark follows. **And it is only offered with the group in hand**: while the name is open, or while the group is folded. Drawn on every expanded group with a done task under it, the sheet grows a column of live deletes down a list somebody is only reading. Collapsed, the icon reads `[X/Y]` — what is still to do, out of what is hidden — and plainly `[Y]` when nothing in there is done, since both halves would be the same number. The icon sits against the title rather than at the end of the row, so the total is the last thing on the line and lands over the prices.
- **Loose ends is a perforation across the paper, not a heading.** It only ever appears because two phones disagreed — a group deleted on one while a task was moved into it on the other — so nothing under it was put there on purpose. There is therefore nothing to name, rename, delete, carry, collapse or add to, and a title row offers every one of those just by looking like one. It is a full-bleed dashed `handLine` with `role="separator"`, drawn at the same weight as the paper's own edges. No title, no rule, no collapse, no add row, and no drop target. `LOOSE_ENDS_TITLE` stays "Loose ends" as the accessible name and as what a keyboard move is announced as; only the mark changes.
- **Enter on the row that makes a group opens its first task**, the same rule an empty group's title follows and the commoner way to reach one, since making a group is what empties it. It commits in the keydown rather than by blurring the field — a blur cannot say whether Enter caused it, and `onblur` must therefore be `() => addGroup()` and never `addGroup`, or the event lands in the argument that decides.
- **The new-group row sits above Loose ends**, since Loose ends is always last and is never something anyone made — under the line it would read as a way to name what is already there. It also takes a drop: a task carried onto it makes a group on the spot and becomes its first, arriving unnamed. `NEW_GROUP` is a sentinel group id rather than a second kind of drop target, because everything between the hit test and the drop already speaks in group ids, and `targetAt` has to check it first — the row sits between groups rather than inside one, so nothing else would find it.
- A task offers its delete mark only when it is done. Not on hover, not on focus — a live delete beside every row a finger passes over, left behind after an un-tick.
- **The delete mark is something scribbled out** (`handScribble`), not a ✕. The one exception is the corner fold, which is a place rather than a mark and draws a bin — see above. The ✕ was the checkbox's own two strokes at half the size and a few millimetres from them, so one gesture meant finished and the same gesture meant gone. It is one unlifted stroke — four legs, alternating ends, turns pulled inwards — because separate passes would be hatching, which is shading rather than deletion. **It is one drawing, everywhere**: `SCRIBBLE` in draw/hand fixes the box and the seed, so the mark on a done task and the mark on a group header are the same mark rather than two scribbles that happen to mean the same thing — the seed is the mark's own name, not the row's. The box is `--glyph` tall, level with the checkbox at the other end of the row, and narrower than it is tall, because the column it stands in is narrower than the checkbox and the ink has to keep clear of the paper's drawn edge. The two paddings are therefore different fractions of their own axis: at one fraction for both, four legs in a tall box come out three pixels apart and merge into a smudge. `handCross` stays and stays used: the modal closes with it, and closing is putting something away rather than taking it away.
- Anything set in `.num` lifts by `--num-lift`. Graphe's capitals are drawn riding high above their own baseline, so a mono digit sitting honestly on that baseline reads low beside them — sharing a baseline is not the same as looking level. Measured in a browser like `--cap-lift`, never derived.
- UI labels are uppercased in CSS only. Stored titles and markdown exports keep the casing the user typed.
- **The group's fold icon is set in round brackets, which Graphe draws itself** — `(…)`, `(1/3)`, `(3)`. They run from 20 above the baseline to 1 below against its figures' 19 above to 3 above, so they enclose what they hold and need no correcting. It was square brackets, which Graphe has none of: a substituted face drew them on the true baseline and they sat visibly low, and the fix was a measured lift — a lot of machinery for a character the face has a proper answer to. This is not the markdown checkbox, which keeps its square brackets and its deliberate fallback.
- Anything drawn that sits beside capitals lifts by `--cap-lift`. Graphe's caps ride high in their own line box, so a centred checkbox reads low against them. The value is measured in a browser, not derived — retune it with the face.
- Anything showing user text in caps sets `lang={langOf(text)}` (src/lib/doc/lang.ts). Greek drops the tonos in capitals and browsers only apply that with the language declared — without it Chrome renders μαΐστρος as ΜΑΪ́ΣΤΡΟΣ. Never uppercase in JS to work around it; that would break the CSS-only rule above.
- Limits: 200 chars/task, 100 tasks, 50 chars/group title, 20 groups, 128 KB blob. Enforce at input; merge never discards to fit. Read them from `LIMITS`, never from here — this line has been wrong before.
- Never {@html}, never innerHTML, never eval. `pnpm gates` fails on them.
- All user text is sanitised at the input boundary (src/lib/doc/clean.ts): NFC, no control or bidi characters, capped length in code points.

## Decisions that override the build plan

The build plan is the specification; these were settled after it was written and win where they conflict.

- **`CODE_LENGTH = 12`**, not 8. 48 bits. The salt is frozen at `consumma:v1` — the app's old name, kept because a salt is an address and not a name: the same code under a different salt derives a different roomId and orphans every list that exists. The `consumma:` prefix on the localStorage keys is frozen for the same reason. Neither is a rename that was missed; both are commented where they are declared and §131 has the whole of it. The code is displayed grouped — `5e6b 7c1a 93f2` — for reading aloud; what is stored is bare lowercase hex, and the SYNC input strips whitespace.
- **Nothing is on the page but the sheet and the buttons in its corners.** A burger at the top right opening a side menu that holds sync, share, join, IMPORT/EXPORT/LEAVE, the theme and the credit; the sync mark beside it, which is the one that comes and goes; and the name of the list at the left, where the writing starts. **Both faces carry the same row**: a name at the left and two marks at the right — sync and the burger on the sheet, the theme and the ✕ on the back — so the pill comes out the same width on both and turning the paper does not move it. The panel reserves the ✕'s own column with a padding, since the ✕ is placed like every corner control at `right: var(--corner-x)`, which is exactly where the scroller's content stops. The name is as wide as its own words rather than as wide as the room: filling the line would draw a drop target's loop round half a sheet of nothing and hang the column of lists across the titles a carried group is aimed at. **The corner row keeps `min-height: var(--touch)`**, because it used to be held up by whichever mark stood in it — the pill is an inline-flex box in a shorter line box — and the sheet stepped up ten pixels the moment a group was lifted and both marks left. **The panel's corner mark is the burger again, drawn as a list** (`handList`): the same three rows at the same heights, with a short dash put at the head of each. It is one function with the burger (`bars` in draw/hand.ts) rather than a second drawing of three lines, or retuning one leaves two different hands on the two faces of one sheet. It was a ✕ first, which closes something laid on top and nothing is laid on top here; then `handBack`, an arrow, which said where the tap goes where every other mark in this app says what a thing is — and a button a finger left from is the button it should come back to. `handBack` is gone with it: a drawing nothing draws is weight in the bundle and a second answer waiting to be picked. **The theme is on the back of the sheet**, beside the switcher, which is the other thing in the panel about this device rather than about the writing. It stood in the corner on the reasoning that a control for how the sheet looks cannot be buried under a panel that covers the sheet — but the panel is not over the sheet, it is the other side of it, and turning the paper to reach the switch shows the answer on the way back. It is a glyph and stays unboxed, like the ✕ and the pill it sits beside; `e2e/design.e2e.ts` names all three rather than inferring them. No opening scroll — nothing sits above the sheet. The row is laid out with `margin-left: auto` on the right-hand pair rather than `space-between`, because the switcher is absent until there is a second list and space-between with one child pushes it the wrong way. The sync mark is inside that pair rather than beside it, so both leave together while a group is carried — neither has anything to say to a group in hand, and the corner they stand in is the one that folds down to take it.
- **The theme is two states on one glyph: the opposite of the phone, and following the phone.** A tap goes to the opposite of whatever the phone is doing, and the next comes back to following, so every tap turns the sheet over. The third state — the choice that agreed with the phone — is gone: it drew an identical sheet to following, so the tap into it and the tap out of it both looked like nothing happening. The pair is computed against the phone and turns around with it. The glyph reports the state it is in, not the one a tap would give. Going back to following removes the key rather than writing `system` into it: arriving writes nothing, and returning to the default has nothing to say either.
- **The theme is resolved before the first paint, by static/theme.js.** On two colours a flash is the whole screen, at exactly the moment the app opens. It is a file rather than an inline script because the CSP is `script-src 'self'` and SvelteKit only hashes the scripts it injects itself; it is last in the head so the policy above it governs it, and it is a classic script so it runs before the app's deferred modules. It spells `KEYS.theme` a second time because nothing can be imported from there — tests/theme.spec.ts reads it back off disk and fails if the two drift. Never write `%sveltekit.head%` in prose inside app.html: the placeholder is substituted by plain text replacement, comments included, and a comment naming it swallows the whole head.
- The menu closes before any panel opens over it. Two focus traps at once is a keyboard trap. `src/lib/a11y/trap.ts` is shared by the menu and the modal; do not write a second copy.
- Sync copy comes from `src/lib/sync/status.ts`, never inline. Two lines: how much is waiting, then why it still is. Being unreachable is a condition, not an error, and it never hides the count.
- **A group's name is quoted wherever the app says it back** (`t.group.named`), and never when it is read aloud — a quotation mark is noise or silence depending on the screen reader. Without the quotes "Deleted Weekend and 3 done" leaves the reader to find where the name stopped, and a group called "and" makes a sentence out of nothing. An untitled group has no name to quote and is described instead.
- **Joining never throws a list away.** "Leave them" leaves them where they are: the open list stays on the device and the joined one arrives beside it, as a new list in the switcher. The new list is made before the pull, because it is the list the pull lands in; if the code is wrong or the network is gone, the device goes back to the list it was on and the blank one is dropped as it is left, having written nothing. Read `sync.message` **before** switching back — switching re-points sync at the other list's keys and clears what it had to say.
- **The menu's one destructive button reads LEAVE with a code and DELETE without one.** They are two different acts: with a code the list carries on without this device and can be come back to; without one this device is the only place it has ever been. The confirm agrees with the button that opened it, and so does the message afterwards.
- **Leaving is undoable, and it is the one undo that is an undelete.** Everywhere else an undo stamps forward, or a device that already synced the deletion wins the next merge and re-deletes everything; leaving never reached a merge, so `lists.restore` writes the same bytes back under the same keys. It captures the **whole index**, not the row that went: removing a list rewrites what is left and can take the index away altogether, so putting one row back into that restores the wrong shape and leaves the other list unreachable.
- **Every word the app says lives in `src/lib/i18n/en.ts`**, and `t` in `./index.ts` is a reference to it — no lookup, no key parsing, no locale negotiation. A second language is a second file and a resolver written the day there is something to put in it; `Messages` is derived from the English catalogue so the second one cannot be quietly incomplete. Values are strings, or functions of a typed argument where a count or a name goes inside the sentence, because plural agreement is part of the sentence rather than a decoration on it. Numbers that a limit decides are read from `LIMITS` and never spelled out. `pnpm gates` refuses a literal `aria-label` in a component: an accessible name is the one that gets forgotten, being invisible to anyone looking at the app rather than reading it. What is **not** in the catalogue is anything the person typed — except `doc.firstGroup`, which becomes a real group title and therefore syncs, and is commented there.
- **Arriving writes nothing.** No localStorage key, no persistent-storage request, no code. The first write is the first edit, and it puts down the document, the client id and the clock together. The opening group is scaffolding, not a change: it is added quietly, it is not counted as unsent, and until something real is written the corner button does not appear.
- **A list nobody wrote on is not a list.** The same rule as "arriving writes nothing", carried across the switcher: a new list is the opening group and nothing else until something is put on it, so it is dropped from the index as it is left and its keys go with it — tapping New list, looking at it and going back leaves no trace. It cannot be synced either (`sync.syncable`), because that would mint a code addressing an empty document; having a code already is enough on its own, since that list has been somewhere and pulling what others added is what a sync is for. The legacy entry is never dropped — it holds the bare keys, and once every namespaced list beside it is gone the index itself goes, putting the device back to the shape it had before it ever had two.
- **A code is the address of a list on the server, so it does not exist before the first sync.** `sync.load()` never makes one; `sync()` makes it and writes it down before the request, because a PUT that lands while the confirming read fails would otherwise strand a list under a code nobody kept. Until then the menu shows no code and no SHARE or COPY, and the LEAVE confirm says there is nothing to come back with.
- **SHARE hands over one payload** carrying the link and the code together; either half alone is useless to someone who has neither. It goes in `navigator.share`'s `text` with no `url` field, so no target can keep one and drop the other. Two lines, link then code, with no title and no prose. The link carries the `?j` flag and nothing else — no code, and nothing about the list.
- The JOIN field takes a code out of a pasted invitation and drops the link (`codeFrom` in src/lib/crypto/derive.ts). It never guesses: a URL's own letters are hex enough that `listula.cafe` reads as `acafe`, so words that could be part of a URL are dropped whole and every word left has to belong to the code. Ambiguous input returns null rather than a wrong code.
- **COPY hands over the code alone.** It sits under the code, and what a button under a code copies is the code — for pasting into a message already being written, or into the other phone's JOIN field. This is deliberately not the same payload as SHARE.
- **Sync is entirely manual.** There is no poll interval, no visibilitychange/focus/online trigger, no push debounce, and no queue that flushes on reconnect. One `syncNow()` runs on the SYNC tap and nowhere else, doing both directions, with a 10-second cooldown. The 15-second tick in SyncButton advances the clock and recomputes the mark; it never syncs, and nothing may be added to it that does. §5's `head()` read path and `cacheControlMaxAge: 0` therefore stand as written — the operations budget is no longer under pressure.
- An unsynced edit reaches nobody and dies with the device. Three things carry that, and no fourth is added: the corner button shows an outbox arrow whenever local edits are unsent, the SYNC panel names how many, and the LEAVE confirm says so. No nagging, no auto-sync, no banner.
- Being unable to reach the list is a condition, not an error. It is drawn as a crossed circle on the corner button and it outranks the arrow. It is set by an attempt that actually failed and cleared only by one that succeeded — never inferred from `navigator.onLine`, which says the device has a network, not that the list is at the end of it.
- **No `PUBLIC_BLOB_BASE`** and no `/api/room/[roomId]/version` route. Both are leftovers from a draft where the browser read the CDN directly.
- Stamps use a per-device monotonic clock, `t = max(Date.now(), lastT + 1)`, persisted beside `clientId`. Without it two edits from one device in one millisecond collide on `(t, c)` and merge stops being commutative.
- After a successful `PUT`, re-`GET` once and confirm our stamps came back; if not, merge and retry, bounded at 5 attempts with jittered backoff. Vercel Blob has no compare-and-set, so this is what actually makes a lost write self-healing.
- Crypto envelope is `base64(0x01 ‖ iv ‖ ciphertext)` and the plaintext is always deflate-raw. Compression cannot be optional — a reader cannot tell the two apart — and the version byte buys a future change without orphaning lists.
- Markdown: export `- [~]` for half; import accepts `[ ]`, `[x]`, `[X]`, `[~]`, `[/]`, `[-]`, a bare bullet, and a bare line as to-do. Rules and fenced code are skipped. Input that parses as JSON, or that opens with a tag or is riddled with them, is refused outright and told which it was — read line by line it would arrive as a heap of punctuation.
- **Amounts and costs are read, never stored.** `src/lib/doc/amount.ts` finds a count at the front of a task (`2x`, `3`, `1.5x` — a number, optionally an `x`, then a space) or a measure (`500g`, `1,5 kg`, `2L` — a number and a metric unit: `g`/`gr`, `kg`/`k`, `l`/`lt`, `ml`, any case, written back as `g`, `kg`, `L`, `ml`; no US units, no long spellings), either of which may be a range (`2-3`, `200–300g` — two numbers rising across a hyphen or dash, the `x` or unit once after both, written back with an en dash; a count's range is totalled at its top) and a price at the end (a space, an optional `€`/`$`/`£` on one side only, a number, end of line). The text stays one string: `aria-label`, the markdown export and what merge sees are all untouched. Both `,` and `.` are decimal separators, because both are written; thousands are told apart by the digit pattern — one or two digits behind the last mark makes it a decimal point, exactly three makes it a grouping mark, four is neither and not a price. Values are held in integer minor units. Do not add a currency to the document to make this easier; it is a reading, not a field.
- **A measure is not a count.** `500g Butter 2,50` is one pack at 2,50, so a row with a unit counts once in the total; only `x` or a bare number multiplies. A litre is written `L` because a lowercase one beside a digit reads as a 1.
- **A group writes its numbers one way.** `figures()` reads every priced row in the group, done ones included, and the whole column is written out in the prevailing form: whichever separator the prices used most (a tie to the dot), two decimals if any price wrote any and none if none did, and a currency mark when every price that wrote one wrote the same one — onto the prices that wrote none as well. A count always ends in one `×` and never two, and is never padded with decimals. None of this touches the text: `aria-label` and the export keep every character that was typed.
- The group total is the last thing on the header row, so it stands directly above the price column. It is what is **still to buy**: done does not count, half counts in full. **Each row counts as count × price** — three potatoes at 20,00 is 60,00 — while the row itself keeps showing what one costs, because that is what gets checked against a shelf. A row with no count is one of the thing, not none of it. Nothing to total, nothing shown — and it stays while the group is collapsed, which is when it is worth most.
- **Only the prices are a column.** A count sits in front of the words like the word it stands in for, and a row without one starts where its words start. Do not reserve space for a count on rows that have none — that indents half a list to line up numbers most of it does not have.
- **Every delete mark stands in one column**, out in `--gutter` and out of the row's flow: the one on a done task and the one that clears or removes a group. A delete appearing must move nothing, or the price column stops being a column the moment anything is ticked. It is narrower than `--touch` across and keeps its full height; that is the price of the position.
- **Opening a task takes the caret with it, to where the finger landed.** A person reaching into the middle of a sentence is reaching for the middle of it. Two of the row's own readings stand in the way — the count and the price are lifted into cells of their own, and an address is drawn as what it points at — so `src/lib/doc/caret.ts` carries the offset back through both, using `nameAt` on a `Reading` and `at` on a `Piece`. Inside a link's label the answer is the end of that address, because the label has fewer characters than the address and there is no correspondence to find. A point the row cannot place falls back to the end, which is where the caret always used to go and is what a backspace out of the row beneath expects. Each drawn piece carries its own index rather than being found by counting children: an `{#each}` puts anchor comments among its output, so the nth child is not the nth piece. Without the focus the field never blurs, so the row never commits and never leaves edit mode. Escape therefore has to put the text back **before** it drops the field — removing a focused field blurs it, and the blur commits.
- **Enter cuts the task at the caret** (`splitAt` in doc/spill.ts, beside `spill`, because both answer where the cut falls). What is in front of the caret comes down to the row that opens beneath, which is what Enter does in the middle of a line of writing anywhere else, and the caret goes with it to the **head** of that row — the one exception is a row opened by running out of room, which is still being typed at its end. **A caret truly at the very start opens the empty row above instead**, so the writing goes down a line and an empty one opens over it; the task itself is not touched, since a draft is the only row that may be empty. Truly at the start means a collapsed caret at 0 and not a selection beginning there — double-tapping a word selects it, which is somebody replacing it, and both reach `splitAt` with an empty head.
- The field a task is edited in is a `<textarea>`, so a task drawn over two lines is edited over two lines. Tasks are still one string: `clean` turns any newline into a space at the boundary and Enter never reaches the field as one. It is sized by `src/lib/grow.ts` through the CSSOM, never by a style attribute.
- **A row that runs out of room fills up and the rest starts the next one.** Never `maxlength` — on a phone a field that silently stops accepting characters is indistinguishable from a broken keyboard. `src/lib/doc/spill.ts` decides where the cut falls: at the last space that still leaves a full row, so a word travels whole, and exactly at the limit only when there is no space to use. A paste spills by the same rule as typing.
- The checkbox is aligned to the top of a task, not to its middle: a task that wraps is still one task starting on one line, and the box belongs beside that line. The delete mark sits on that first line too, out in the gutter and out of the row's flow, so it costs the words no width.
- **The checkbox is `--touch` across and stops where the writing starts**, and it is the full height of the row, because a task over three lines has three lines of checkbox beside it. It did reach a third again across, so a finger going for the box and landing on the first word still ticked the task; what that cost was the first word or two, which then belonged to the checkbox — tapping them ticked instead of opening the row, and pressing them could not lift the task at all, since the lift lives on the words and the box was sitting over them. Two of the row's three gestures went missing at the one end of the row a finger goes to, which is the dearer mistake. It stays positioned against the row rather than in the flow, and the row pads itself by exactly what the box occupies: changing its width in the flow would move every line on the sheet sideways. The same geometry is written twice, in TriCheckbox and in AddRow's ghost box.
- **An open add row's box is faint while it is empty and full ink once something is written in it.** An empty row is still an offer and is drawn as faintly as the ellipsis it replaced; the moment there is writing it is a task, so its box stops being a suggestion. Nothing moves — only the weight of the line changes. `.written` is declared after `.shown` in AddRow, because the two are the same specificity and source order is what decides.
- **The count of what is left is late and low**: from ten characters (`COUNTER_WITHIN`), under the checkbox and stuck to the foot of the row. The writing is being done at the bottom of a long row, so the count belongs there rather than in the gutter beside the first line, which is the one part of a long task nobody is looking at. One `Counter.svelte` for the task row and the add row. It counts down and never below nought, because at the limit the row fills up and the rest starts the next one. Note that `.num` lifts every figure with a relative `top`; positioned, that `top` becomes an edge, so the counter sets `top: auto` or an absolute box given both stretches the height of the row.
- **Links in a task are read, never stored** (`src/lib/doc/links.ts`), the way the count and the price are. Three schemes and no others — `https`, `http`, `mailto` — checked on the parsed URL, and an address is only recognised where one can start, or `blob:https://…` links to whatever is inside it. Shown without the protocol and with the middle of the path elided; the href keeps every character.
- The link underline is the one `background-image` in the app, and the one drawn mark that is not an inline `<svg>`: a link is inline text that wraps and every line box wants its own mark. The tile comes from `handUnderlineTile` and is set on the document by `+layout.svelte`, in the colour the theme resolved to — a data URI cannot read `--ink`. `img-src` allows `data:` for that and nothing else; `connect-src` stays `'self'` alone.
- Backspace is the other half of Enter, at two lengths. On a row with nothing left in it, the row goes and the caret carries on at the end of the task above; an emptied task is deleted through the ordinary path, so the ordinary undo covers it. **A row still being typed with no task above it goes up to the group's own name instead**, since that is what opened it — Enter on an empty group's title puts the row there, and this is the same motion in reverse. **With a collapsed caret at the very start of a row that still has something in it, the two tasks become one** and the caret waits at the seam — a row still being typed included, since on the sheet a draft and a task are the same thing and only the draft has nothing to delete afterwards. That one is quiet — no message and no undo, because nothing was taken away and a "Deleted." toast would be a lie about the one thing it is there to report — and it is refused outright when the two would not fit in one task, since dropping the overflow to make them fit would lose writing.
- The import modal previews the parsed list, in the notation it would be exported in, before anything is applied. It is the only honest preview once a line without a bullet becomes a task. Written as text, never as markup — nothing here renders HTML.
- Haptics live in `src/lib/feel.ts` and are three lengths: a tap for something done, dot-dot for something taken away, dot-dot-dash for something finished. Nothing longer — anything with rhythm enough to read as a message is a notification, and this app does not send those. **Every button taps, and so does a turn that goes over**, called explicitly at each site rather than delegated from the root: a single listener would have to be told to stand aside wherever a more specific answer already fires, and an opt-out is a worse thing to maintain than a call. A control that answers back sometimes reads as broken rather than as quiet.
- **The toast comes down from above the paper and goes back up the same way**, and can be thrown out by hand — up or right, since down is the sheet's own scrolling and left is the way the paper turns. Leaving needs the node to stay in the document while the movement runs, so `ui.dismiss()` starts it leaving and `ui.gone()` removes it; an undo passes `now`, because it replaces the very thing the message was about. Thrown clear rather than played back up: sliding it home first would be the message arguing with the hand that had just moved it. Note that Svelte scopes the keyframes a component declares, so `animationName` in a handler carries a hash and can never be compared to the name in the file — the leaving end is told by state instead.
- QR code in SHARE and a "move everyone to a new code" flow are **out of scope**. Work stops at M7.
- CSP names two framework Trusted Types policies, `svelte-trusted-html` (Svelte's own template writes) and `sveltekit-trusted-url` (the service worker registration). Chrome will not hydrate without the first; SvelteKit will not build without the second. `style-src` carries one pinned hash under `'unsafe-hashes'` for SvelteKit's `#svelte-announcer`, which is framework markup we do not author — that is not `'unsafe-inline'`, and e2e/csp.e2e.ts fails on any console error if it drifts.
- The ETag on a room is the document's own version, never the blob's upload time and size: two writes in one millisecond with same-length JSON collide, and the second is reported unchanged.
- Client JavaScript stays under 100 KB gzipped (`pnpm budget`, enforced in CI).
- PWA icons are drawn by scripts/icons.ts at build time into static/icons, which is gitignored. The asset gate exempts that directory only while it stays gitignored. The mark is `[x]`, drawn — brackets included, since Graphe has none and an icon cannot fall back.
- **The launch screen starts from black, and the home screen does not.** The manifest's `background_color` and `theme_color` are both `#000000`, and the two plain icons are drawn white-on-black to sit on that ground rather than as a white card in the middle of it. The maskable icon and apple-touch-icon stay black-on-white: those are the tiles a phone cuts its home-screen icon from, and the mark sitting among other apps is not the place to make a statement about the theme. A manifest cannot ask what the phone is set to, so this is one colour for everybody and black is the one to be wrong in — opening the app is the moment a white screen is least wanted and most likely to be followed by a black one. Which icon a browser picks for a splash is not in the specification; a version reaching for the maskable one shows the mark on white, which is a worse splash rather than a broken one. The page takes the tint over from the manifest as soon as it loads, so none of this governs anything past the launch.
- iOS ignores the manifest for its launch screen and wants `apple-touch-startup-image` per device size. There are none, so an installed iOS app still opens on its own white screen. Known, and left.
- The page is prerendered (`prerender = true` in `src/routes/+layout.ts`). Only `/api/*` is dynamic.
- `src/lib/server/store.ts` is the only file that imports `@vercel/blob`.
- One typeface, everywhere — §6's two faces are down to one. There is exactly one `@font-face` in src/app.css and one variable, `--hand`, that names it; titles and body separate by size and caps. The face is Graphe, the owner's own and not open-licensed; a fork that publishes must substitute its own, licensed for webfont embedding and redistribution. The single exception is `.num`, a recognised amount or cost, set in `--mono` — a system stack, so it is still one `@font-face`, one file and no request. Nothing else may leave the hand, and `e2e/design.e2e.ts` names the carve-out rather than inferring it.
- Scale corrections for the face live in `size-adjust`/`ascent-override`/`descent-override` on that one `@font-face`, never spread across `--size-*`. Graphe is drawn on a much larger body than the rem values assume. Swapping the face means retuning those three and the preload in src/app.html — a stale preload fails the prerender rather than shipping a dead link.
- Graphe has no `[`, `]` or `\`; they fall back deliberately. Never rewrite the markdown checkbox tokens to work around it — the export has to stay readable by other apps.

## Style

- Svelte 5 runes ($state/$derived/$effect), no legacy stores.
- No CSS framework, no component library, no crypto library.
- Config lives in `vite.config.ts` — this scaffold has no `svelte.config.js`. `sveltekit()` takes the kit config directly.
- Every new module gets a test before it gets wired to the UI.
- Relative imports inside src/lib/draw use explicit `.ts` specifiers, because scripts/icons.ts runs them through Node's type stripping, which does not resolve extensionless paths.
- Playwright never reuses an existing preview server. A stale one serves an old build and every failure then points at the wrong thing.
